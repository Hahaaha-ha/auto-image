# 软件版本制作总结

仅在用户手动调用本 skill 时运行。先读取 [软件版本文件交接约定](../../deploy-records.md)，运行 `python scripts/deploy_record.py schema` 获取当前字段和总结结构。总结只读当前版本材料并写文档，不派发 deploy 阶段，不执行远程、安装、验证、清理、制镜像、切 OS、上传或上架操作，不产生部署阶段事件或任务。

## 1. 确定软件、版本与人工反馈

从当前会话准确取得软件、实际版本及目标目录；跨会话明确软件/版本后读取固定目录的当前指南、安装、验证、归档、pipeline-result 和元数据。软件/版本或机器有歧义时先确认，不能按最近目录猜选。已有 run_id/task_id 可作为来源，没有 Web 上下文则注明。

已有镜像就核对当前 image_id/job_id；尚未生成则如实记录未生成，不要求补不存在的镜像。用户明确反馈已上架时，核对反馈对应最终 image_id，写明反馈时间与原意；对应关系不明先请求补充。打包成功、上传或审核提交均不能替代上架反馈，不增加文档审批步骤。

成功版本在工作收尾时由用户手动总结。失败不要求专门总结或归档；用户明确要求总结未完成状态时才按现状整理，保留缺口且不进入成功复用候选。

## 2. 整理当前有效内容

按 schema.summary_sections 和 [总结模板](references/template.md) 核对软件与环境、制作来源、复用基准、有效步骤、安装详情、版本差异、修正经验、验证与缺口和本次更新说明。

- 记录实际最终有效的准备、依赖、安装、配置、启动、验证及打包步骤，具体命令、非敏感参数、环境变量、目录、服务、端口及所需脚本应可查。必要配置/脚本置于当前版本目录附件中，保持与正文一致；秘密值只记参数名及获取方式。
- 用户建议与 agent 实际执行分开，未执行建议不写成成功步骤。失败过程不额外归档，只在确实有助于后续复用时概述已确认问题及最终修正，不收集完整失败历史。
- 版本差异以本次实际基准为准；无基准仍整理完整有效步骤。另选比较对象时明确版本与路径。功能变化只写已有官方依据，跨大版本比较不意味着复用旧安装步骤。
- 验证结果须对应当前最终安装和镜像，旧结果不能替代实测。未执行诊断与缺失材料如实写明；只在真正从基础环境重新执行过时记复现结论，本 skill 不创建机器补验证。
- 当前总结、元数据和附件一并覆盖，候选校验只读取当前文件。按 schema 填 body 正文、人工反馈、当前 evidence 文件路径、最终镜像、source 与 gaps；有效步骤和必要材料在正文检查，不引入修订历史或不可变证据要求。候选资格要求人工上架反馈、对应最终镜像、实际环境与适用验证及必要材料，不能凭一个完整标记认定。

## 3. 覆盖版本总结

通过 `paths --software <软件> --version <版本>` 取得同目录 summary_file。按模板生成完整正文，将 body 正文、人工反馈、当前材料与覆盖检查写入 schema 对应 JSON，核对链接、实际版本及最终镜像后保存：

```bash
python scripts/deploy_record.py save-summary --software <软件> --version <版本> --data <当前总结JSON文件>
```

入口原子覆盖 `<output_dir>/<software>-summary.md` 与当前状态的 summary。同软件同版本重复调用覆盖当前内容，不新建总结目录、备份或修订，不调用 begin-stage。材料不完整时如实记缺口，候选校验排除；无需保留失败或覆盖前的正文。

回复软件/实际版本、summary 路径、当前复用资格与原因、必要缺口。总结完成不触发部署或云操作。
