# 软件部署总结

仅在用户手动调用时运行。先读取 [部署总结参考](../../deploy-summary.md)，按其中的软件身份、路径、记录字段和阅读原则处理。本 skill 只阅读现有材料并保存总结/必要附件；不修改阶段报告、安装 meta、机器、云资源或任务状态，不派发部署阶段，不执行远程、验证、上传或云操作。

## 1. 核对对象与已有材料

从会话、用户指定路径和已有阶段目录核对软件、版本、已确认官方来源及保存位置；沿用本次已有路径解析结果，需要补齐总结路径时按共享参考解析。读取与本次总结有关的指南、安装/验证结果、配置、脚本及已有归档报告；材料可以不齐全。软件或目标路径确有歧义时澄清，已有明确上下文则继续整理，不按最近修改时间猜任务。

只把已有证据支持的实际版本和环境填入记录，未知按共享参考留空。已有机器、镜像或人工上传/审核/上架反馈按需写正文，注明来源及不确定处；未生成镜像、未上架或反馈关联不清都不阻断总结。用户要求总结失败或未完成尝试时按实情记录。

## 2. 整理正文

使用 [总结模板](references/template.md) 组织有用内容，按实际材料保留或省略章节；它不是必须补齐的清单。

- 把关键安装与配置步骤写进正文：实际来源、命令、参数、路径、服务、端口和必要配置，避免只链接以后可能覆盖的报告。未实际执行的指南命令标为计划或参考。
- 写清哪些验证实际执行并通过、哪些失败、未执行或无法判定；已有镜像与机器关联按证据记录。缺少信息如实注明，不为凑齐材料补跑验证或生成镜像。
- 保存有用的已确认问题和最终有效修正，用户建议与已执行操作分开。失败步骤不能写成成功经验。
- 参考来源及版本、依赖、配置差异只写已有依据；无需为总结增加网络调查。附件优先引用已有文件，确需补充时仅保存已有材料中的非敏感内容；秘密值只记参数名及获取方式。

## 3. 保存并确认

按共享参考准备扁平 JSON，包含明确的总结 `path`、`software`、`version`（未知为 `null`）、已有证据中的 `project_url` / `canonical_name`（若有）、环境字段与 `body`。沿用现有总结路径或解析结果的 `files.summary_file`；`body` 只含正文，规范软件名与文件头由脚本生成：

```bash
python scripts/deploy_summary.py save --data <总结输入JSON文件>
```

确认命令成功，读取返回 `path` 的 Markdown，核对文件头记录和正文确已保存。同软件同版本再次手动调用覆盖原总结；其他部署操作不更新总结。保存失败则报告具体错误，不声称保存成功，不修改部署结果。

回复软件/实际版本、已保存的总结路径及必要缺口。总结完成后不自动启动其他流程。
